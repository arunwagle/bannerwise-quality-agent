# Bannerwise Quality Agent — Per-Query Cost Attribution Design

## 1. Design Philosophy

**Principle:** Leverage existing Databricks infrastructure (MLflow Tracing, AI Gateway usage tables, Query History) rather than building a parallel observability system.

**Goal:** Compute total cost per user query, enable cost estimation from historical patterns, and identify expensive queries — all using native platform capabilities.

---

## 2. Architecture Overview

```
┌──────────────────────────────────────────────────────────────────────┐
│  User Query (turn_id generated at entry)                             │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  Flask App (orchestrator — owns all audit writes)                    │
│  ├─ MLflow Trace (root span, turn_id as attribute)                   │
│  │                                                                   │
│  ├─ Serving Endpoint call ──► Router PyFunc                          │
│  │   ├─ VS Hybrid Search ─── span: ai_search                        │
│  │   └─ LLM Judge (1-3x) ── AI Gateway (request_tags: turn_id)      │
│  │                                                                   │
│  ├─ [Certified Lane]                                                 │
│  │   ├─ LLM Param Extraction ── AI Gateway (request_tags: turn_id)   │
│  │   ├─ SQL Validation ──────── statement_id captured                │
│  │   └─ SQL Execution ──────── statement_id captured                 │
│  │                                                                   │
│  └─ [Analytical Lane]                                                │
│      └─ Genie API call ──────── time-window correlation              │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│  Cost Reconciliation (scheduled job — joins system tables)           │
│  ├─ system.ai_gateway.usage     (exact: tokens per LLM call)        │
│  ├─ system.query.history         (exact: DBU per SQL statement)      │
│  ├─ system.billing.usage         (allocated: VS endpoint, Genie)     │
│  └─ Materialized: cost_per_query (final per-turn cost view)         │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. Correlation Model

### 3.1 Identity Hierarchy

```
conversation_id   — stable across a user session (multiple questions)
  └─ turn_id      — ONE user question + its full execution lifecycle
       └─ span_id — individual operation within a turn (MLflow span)
```

| Field | Format | Generated By | Purpose |
| --- | --- | --- | --- |
| `conversation_id` | UUID v4 | App (session start) | Group queries in a session |
| `turn_id` | UUID v4 | App (per request) | **Primary cost attribution key** |
| `span_id` | MLflow auto | MLflow Tracing | Per-operation granularity |
| `trace_id` | MLflow auto | MLflow Tracing | Links all spans in one turn |

### 3.2 Context Propagation

```python
@dataclass(frozen=True)
class RequestContext:
    conversation_id: str
    turn_id: str
    trace_id: str | None = None  # Set after MLflow trace starts

    def as_gateway_tags(self) -> str:
        """Format for AI Gateway request tags header."""
        return json.dumps({
            "conversation_id": self.conversation_id,
            "turn_id": self.turn_id,
        })
```

**Propagation path:**

| Boundary | Mechanism |
| --- | --- |
| App → AI Gateway (LLM calls) | `Databricks-Ai-Gateway-Request-Tags` HTTP header |
| App → Serving Endpoint (router) | Additional field in model input DataFrame |
| App → SQL Warehouse | Capture `statement_id` from response |
| App → Genie | Record `start_time` / `end_time` + Genie `conversation_id` |
| Within App | In-process `RequestContext` (thread-local or async context) |

## 4. Cost Capture by Component

### 4.1 LLM Calls (Exact Attribution)

**Source:** `system.ai_gateway.usage`

All LLM calls (judge, parameter extraction) flow through AI Gateway. The app tags each with `turn_id` via the request-tags header.

**How to tag (from app service layer):**

```python
from databricks.sdk import WorkspaceClient

w = WorkspaceClient()
response = w.serving_endpoints.query(
    name="databricks-meta-llama-3-3-70b-instruct",
    messages=[...],
    extra_headers={
        "Databricks-Ai-Gateway-Request-Tags": ctx.as_gateway_tags()
    }
)
```

**How to tag (from PyFunc router — judge calls):**

The router PyFunc receives `turn_id` in the model input and passes it to judge calls:

```python
def predict(self, context, model_input: pd.DataFrame) -> pd.DataFrame:
    for _, row in model_input.iterrows():
        prompt = row["prompt"]
        turn_id = row.get("turn_id", "")  # Passed by app
        # ... pass turn_id to _judge_candidate
```

```python
def _judge_candidate(self, w, prompt, row, turn_id=""):
    response = w.serving_endpoints.query(
        name=self.judge_model,
        messages=[...],
        extra_headers={
            "Databricks-Ai-Gateway-Request-Tags": json.dumps({
                "turn_id": turn_id,
                "component": "judge"
            })
        }
    )
```

**Query: LLM cost per turn**

```sql
SELECT
    request_tags['turn_id'] AS turn_id,
    request_tags['component'] AS component,
    endpoint_name AS model,
    COUNT(*) AS llm_calls,
    SUM(input_tokens) AS input_tokens,
    SUM(output_tokens) AS output_tokens,
    SUM(total_tokens) AS total_tokens,
    SUM(latency_ms) AS total_latency_ms
FROM system.ai_gateway.usage
WHERE request_tags['turn_id'] IS NOT NULL
  AND event_time >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY 1, 2, 3
ORDER BY total_tokens DESC
```

### 4.2 SQL Warehouse (Exact Attribution)

**Source:** `system.query.history`

The app executes SQL via the Statement Execution API (for certified lane) and captures the `statement_id` from the response.

**How to capture:**

```python
# In certified_lane_service.py — SQL execution already returns statement_id
response = w.statement_execution.execute_statement(
    warehouse_id=warehouse_id,
    statement=bound_sql,
)
statement_id = response.statement_id  # ← capture this
```

**Query: SQL cost per turn**

```sql
SELECT
    qh.statement_id,
    qh.executed_as_user_name,
    qh.total_duration_ms,
    qh.rows_produced,
    qh.metrics.total_task_duration_ms,
    qh.metrics.read_bytes,
    qh.metrics.read_rows,
    -- DBU approximation based on warehouse type and duration
    ROUND(qh.total_duration_ms / 1000.0 / 3600.0 * warehouse_dbu_rate, 6) AS estimated_dbu
FROM system.query.history qh
WHERE qh.statement_id IN (
    -- statement_ids captured by app for a specific turn
    SELECT statement_id FROM observability.turn_statements
    WHERE turn_id = :turn_id
)
```

### 4.3 Vector Search (Allocated)

**Source:** `system.billing.usage` (endpoint-level)

AI Search does not expose per-query cost or a caller-metadata field. Cost is allocated proportionally.

**Allocation strategy:**
- Track number of VS calls per turn (from MLflow spans or app audit)
- Divide hourly endpoint DBU cost equally across all calls in that hour

**Query: VS endpoint hourly cost**

```sql
SELECT
    usage_date,
    DATE_TRUNC('hour', usage_start_time) AS hour,
    SUM(usage_quantity) AS dbus,
    SUM(usage_quantity * list_price) AS dollar_cost
FROM system.billing.usage
WHERE usage_metadata.endpoint_name = 'bannerwise-vs-endpoint'
  AND usage_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY 1, 2
ORDER BY 1, 2
```

**Per-turn allocation:**

```sql
WITH hourly_cost AS (
    SELECT
        DATE_TRUNC('hour', usage_start_time) AS hour,
        SUM(usage_quantity * list_price) AS hour_cost
    FROM system.billing.usage
    WHERE usage_metadata.endpoint_name = 'bannerwise-vs-endpoint'
    GROUP BY 1
),
hourly_calls AS (
    SELECT
        DATE_TRUNC('hour', start_time) AS hour,
        COUNT(*) AS total_calls
    FROM observability.turn_operations
    WHERE component = 'AI_SEARCH'
    GROUP BY 1
)
SELECT
    ops.turn_id,
    hc.hour_cost / NULLIF(hcalls.total_calls, 0) AS allocated_vs_cost
FROM observability.turn_operations ops
JOIN hourly_cost hc ON DATE_TRUNC('hour', ops.start_time) = hc.hour
JOIN hourly_calls hcalls ON hc.hour = hcalls.hour
WHERE ops.component = 'AI_SEARCH'
```

### 4.4 Genie / Analytical Lane (Allocated)

**Source:** `system.billing.usage` (Genie workspace-level)

Genie is a black box — it internally makes LLM calls and SQL executions that are not individually attributable. Cost is time-window correlated.

**Allocation strategy:**
- Record `start_time` and `end_time` of each Genie API call
- Attribute Genie billing in that window proportionally

**Query: Genie cost by time window**

```sql
SELECT
    usage_date,
    usage_metadata.genie_space_id,
    SUM(usage_quantity) AS dbus,
    SUM(usage_quantity * list_price) AS dollar_cost
FROM system.billing.usage
WHERE sku_name LIKE '%GENIE%'
  AND usage_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY 1, 2
```

### 4.5 Serving Endpoint Compute (Allocated)

**Source:** `system.billing.usage`

The serving endpoint (`bannerwise-quality-router`) has a provisioned cost. Allocated per request.

```sql
SELECT
    usage_date,
```

Maintain a versioned rate card for dollar-cost computation:

```sql
    input_token_rate    DECIMAL(12, 8),   -- $ per token
    output_token_rate   DECIMAL(12, 8),   -- $ per token

    effective_to        DATE,             -- NULL = current
    source              STRING            -- 'databricks_pricing_page', 'custom'
);

-- Example rates (Databricks Foundation Models, as of 2025)
INSERT INTO observability.cost_rates VALUES
('databricks-meta-llama-3-3-70b-instruct', 0.00000100, 0.00000300, '2025-01-01', NULL, 'databricks_pricing_page');
```

**Query: Dollar cost per turn (LLM only)**

```sql
SELECT
    u.request_tags['turn_id'] AS turn_id,
    u.endpoint_name,
    u.input_tokens,
    u.output_tokens,
    ROUND(u.input_tokens * r.input_token_rate + u.output_tokens * r.output_token_rate, 6) AS llm_cost_usd
FROM system.ai_gateway.usage u
JOIN observability.cost_rates r
  ON u.endpoint_name = r.model_name
  AND u.event_time::DATE BETWEEN r.effective_from AND COALESCE(r.effective_to, '2099-12-31')
WHERE u.request_tags['turn_id'] IS NOT NULL
```

## 6. Materialized Cost View (Per-Query Total)

A reconciliation job (hourly) materializes the final cost-per-query view:

```sql
CREATE OR REPLACE TABLE observability.cost_per_query AS
WITH llm_cost AS (
    SELECT
        request_tags['turn_id'] AS turn_id,
        request_tags['conversation_id'] AS conversation_id,
        SUM(input_tokens) AS total_input_tokens,
        SUM(output_tokens) AS total_output_tokens,
        SUM(total_tokens) AS total_tokens,
        COUNT(*) AS llm_call_count,
        SUM(input_tokens * r.input_token_rate + output_tokens * r.output_token_rate) AS llm_cost_usd
    FROM system.ai_gateway.usage u
    JOIN observability.cost_rates r
      ON u.endpoint_name = r.model_name
      AND u.event_time::DATE BETWEEN r.effective_from AND COALESCE(r.effective_to, '2099-12-31')
    WHERE request_tags['turn_id'] IS NOT NULL
    GROUP BY 1, 2
),
sql_cost AS (
    SELECT
        ts.turn_id,
        COUNT(*) AS sql_statement_count,
        SUM(qh.total_duration_ms) AS total_sql_ms,
        SUM(qh.metrics.read_bytes) AS total_bytes_read
    FROM observability.turn_statements ts
    JOIN system.query.history qh ON ts.statement_id = qh.statement_id
    GROUP BY 1
),
vs_cost AS (
    SELECT
        ops.turn_id,
        COUNT(*) AS vs_call_count,
        SUM(hc.hour_cost / NULLIF(hcalls.total_calls, 0)) AS allocated_vs_cost_usd
    FROM observability.turn_operations ops
    JOIN (
        SELECT DATE_TRUNC('hour', usage_start_time) AS hour,
               SUM(usage_quantity * list_price) AS hour_cost
        FROM system.billing.usage
        WHERE usage_metadata.endpoint_name = 'bannerwise-vs-endpoint'
        GROUP BY 1
    ) hc ON DATE_TRUNC('hour', ops.start_time) = hc.hour
    JOIN (
        SELECT DATE_TRUNC('hour', start_time) AS hour, COUNT(*) AS total_calls
        FROM observability.turn_operations WHERE component = 'AI_SEARCH'
        GROUP BY 1
    ) hcalls ON hc.hour = hcalls.hour
    WHERE ops.component = 'AI_SEARCH'
    GROUP BY 1
)
SELECT
    t.turn_id,
    t.conversation_id,
    t.lane,
    t.query_text,
    t.timestamp,
    -- LLM
    COALESCE(l.llm_call_count, 0) AS llm_calls,
    COALESCE(l.total_tokens, 0) AS total_tokens,
    COALESCE(l.llm_cost_usd, 0) AS llm_cost_usd,
    -- SQL
    COALESCE(s.sql_statement_count, 0) AS sql_statements,
    COALESCE(s.total_sql_ms, 0) AS sql_duration_ms,
    COALESCE(s.total_bytes_read, 0) AS sql_bytes_read,
    -- VS
    COALESCE(v.vs_call_count, 0) AS vs_calls,
    COALESCE(v.allocated_vs_cost_usd, 0) AS vs_cost_usd,
    -- Total
    COALESCE(l.llm_cost_usd, 0)
      + COALESCE(v.allocated_vs_cost_usd, 0) AS total_cost_usd
FROM observability.turn_metadata t
LEFT JOIN llm_cost l ON t.turn_id = l.turn_id
LEFT JOIN sql_cost s ON t.turn_id = s.turn_id
LEFT JOIN vs_cost v ON t.turn_id = v.turn_id
```

## 7. Cost Estimation Model

Use historical `cost_per_query` data to predict cost before execution.

### 7.1 Cost Profiles by Lane

```sql
-- Average cost by routing lane
SELECT
    lane,
    COUNT(*) AS query_count,
    ROUND(AVG(total_cost_usd), 6) AS avg_cost,
    ROUND(PERCENTILE(total_cost_usd, 0.50), 6) AS p50_cost,
    ROUND(PERCENTILE(total_cost_usd, 0.95), 6) AS p95_cost,
    ROUND(MAX(total_cost_usd), 6) AS max_cost,
    ROUND(AVG(llm_calls), 1) AS avg_llm_calls,
    ROUND(AVG(total_tokens), 0) AS avg_tokens
FROM observability.cost_per_query
WHERE timestamp >= CURRENT_DATE - INTERVAL 30 DAYS
GROUP BY lane
```

**Expected result (illustrative):**

| Lane | Avg Cost | P95 Cost | Avg LLM Calls | Avg Tokens |
| --- | --- | --- | --- | --- |
| certified | $0.0012 | $0.0025 | 2.3 (judge + param extraction) | 1,800 |
| analytical | $0.0035 | $0.0080 | 1.2 (judge only; Genie handles rest) | 900 + Genie allocated |

### 7.2 Pre-Execution Cost Estimate

Before executing, estimate cost from the routing decision:

```python
def estimate_query_cost(lane: str, candidates_evaluated: int) -> dict:
    """Estimate cost based on historical patterns."""
    # Base costs from historical averages (refreshed daily)
    COST_PROFILES = {
        "certified": {
            "judge_per_call": 0.00035,      # ~600 tokens avg per judge call
            "param_extraction": 0.00045,     # ~800 tokens
            "sql_execution": 0.00005,        # negligible for simple queries
            "vs_search": 0.00002,            # allocated
        },
        "analytical": {
            "judge_per_call": 0.00035,
            "genie_allocated": 0.0025,       # Genie black-box average
            "vs_search": 0.00002,
        },
    }

    profile = COST_PROFILES.get(lane, COST_PROFILES["analytical"])
    estimate = profile["vs_search"] + (profile["judge_per_call"] * candidates_evaluated)

    if lane == "certified":
        estimate += profile["param_extraction"] + profile["sql_execution"]
    else:
        estimate += profile["genie_allocated"]

    return {
        "estimated_cost_usd": round(estimate, 6),
        "confidence": "high" if lane == "certified" else "medium",
        "note": "Genie cost is allocated average" if lane == "analytical" else None,
    }
```

### 7.3 Expensive Query Detection

```sql
-- Top 20 most expensive queries in last 7 days
SELECT
    turn_id,
    lane,
    query_text,
    total_cost_usd,
    llm_calls,
    total_tokens,
    sql_duration_ms,
    timestamp
FROM observability.cost_per_query
WHERE timestamp >= CURRENT_DATE - INTERVAL 7 DAYS
ORDER BY total_cost_usd DESC
LIMIT 20
```

```sql
-- Queries exceeding 3x the lane average (anomalies)
WITH lane_stats AS (
    SELECT lane, AVG(total_cost_usd) AS avg_cost, STDDEV(total_cost_usd) AS std_cost
    FROM observability.cost_per_query
    WHERE timestamp >= CURRENT_DATE - INTERVAL 30 DAYS
    GROUP BY lane
)
SELECT
    q.turn_id,
    q.lane,
    q.query_text,
    q.total_cost_usd,
    ROUND(q.total_cost_usd / s.avg_cost, 1) AS cost_multiple,
    q.llm_calls,
    q.total_tokens
FROM observability.cost_per_query q
JOIN lane_stats s ON q.lane = s.lane
WHERE q.total_cost_usd > s.avg_cost + (3 * s.std_cost)
  AND q.timestamp >= CURRENT_DATE - INTERVAL 7 DAYS
ORDER BY cost_multiple DESC
```

## 9. MLflow Tracing Integration

Rather than building custom tracing, use MLflow's existing tracing as the in-process backbone:

```python
import mlflow
from mlflow.entities import SpanType

@mlflow.trace(name="query_router", span_type=SpanType.CHAIN)
def handle_query(request_context: RequestContext, prompt: str):
    """Root span — all sub-operations are nested automatically."""
    # Set turn_id on root span for later correlation
    mlflow.update_current_trace(
        tags={"turn_id": request_context.turn_id,
              "conversation_id": request_context.conversation_id}
    )

    # Sub-operations create child spans automatically
    routing_result = call_serving_endpoint(prompt, request_context)

    if routing_result["lane"] == "certified":
        answer = execute_certified_lane(routing_result, request_context)
    else:
        answer = execute_analytical_lane(prompt, request_context)

    return answer
```

**Query MLflow traces for cost correlation:**

```sql
-- Join MLflow traces to AI Gateway usage via turn_id
SELECT
    t.trace_id,
    t.tags['turn_id'] AS turn_id,
    t.execution_duration_ms AS total_duration,
    u.total_tokens,
    u.input_tokens,
    u.output_tokens
FROM mlflow.default.traces t
JOIN system.ai_gateway.usage u
  ON u.request_tags['turn_id'] = t.tags['turn_id']
WHERE t.timestamp_ms >= UNIX_MILLIS(CURRENT_DATE - INTERVAL 7 DAYS)
```

## 10. Reconciliation Job

A scheduled job (hourly) materializes `cost_per_query` by joining:

1. `observability.turn_metadata` (app-written, has turn_id + lane + timestamp)
2. `system.ai_gateway.usage` (LLM tokens, joined on `request_tags['turn_id']`)
3. `system.query.history` (SQL cost, joined on `statement_id` via `turn_statements`)
4. `system.billing.usage` (VS + Genie allocated cost, joined by time window)

**Reconciliation handles:**
- AI Gateway ingestion latency (rows may arrive minutes after the call)
- Idempotent upserts (re-running reconciliation doesn't double-count)
- Missing data gracefully (LEFT JOINs — partial cost is better than no cost)

```sql
-- Reconciliation job: update cost_per_query
MERGE INTO observability.cost_per_query target
USING (
    -- The full cost CTE from Section 6
    ...
) source
ON target.turn_id = source.turn_id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *
```

## 11. Dashboarding & Alerting

### 11.1 Key Metrics to Surface

| Metric | Granularity | Alert Threshold |
| --- | --- | --- |
| Cost per query (avg) | Hourly | > 2x 7-day average |
| Total daily cost | Daily | > budget cap |
| P95 query cost | Daily | > $0.01 |
| Token consumption | Hourly | > 10x hourly average |
| Expensive query count | Daily | > 5 queries exceeding 5x average |
| Certified vs. Analytical ratio | Daily | Certified < 30% (corpus coverage gap) |

### 11.2 Sample Alert Query

```sql
-- Alert: hourly cost exceeds 2x the 7-day hourly average
WITH hourly_avg AS (
    SELECT AVG(hourly_cost) AS baseline
    FROM (
        SELECT DATE_TRUNC('hour', timestamp) AS hr, SUM(total_cost_usd) AS hourly_cost
        FROM observability.cost_per_query
        WHERE timestamp BETWEEN CURRENT_TIMESTAMP - INTERVAL 7 DAYS
                             AND CURRENT_TIMESTAMP - INTERVAL 1 HOUR
        GROUP BY 1
    )
),
current_hour AS (
    SELECT SUM(total_cost_usd) AS current_cost
    FROM observability.cost_per_query
    WHERE timestamp >= DATE_TRUNC('hour', CURRENT_TIMESTAMP)
)
SELECT
    current_cost,
    baseline,
    ROUND(current_cost / NULLIF(baseline, 0), 1) AS cost_multiple
FROM current_hour, hourly_avg
WHERE current_cost > baseline * 2
```

## 12. Cost Attribution Summary

| Component | Attribution | Source Table | Join Key |
| --- | --- | --- | --- |
| LLM (Judge) | **Exact** | `system.ai_gateway.usage` | `request_tags['turn_id']` |
| LLM (Param Extraction) | **Exact** | `system.ai_gateway.usage` | `request_tags['turn_id']` |
| SQL Warehouse | **Exact** | `system.query.history` | `statement_id` |
| Vector Search | Allocated | `system.billing.usage` | Time-window + endpoint name |
| Genie | Allocated | `system.billing.usage` | Time-window + space ID |
| Serving Endpoint Infra | Allocated | `system.billing.usage` | Time-window + endpoint name |

**Exact** = per-request granularity, directly attributable
**Allocated** = endpoint-level cost divided across requests in that time window

## 13. Implementation Phases

| Phase | Scope | Effort |
| --- | --- | --- |
| **Phase 1** | Add `turn_id` to model input + AI Gateway request tags. Create `turn_metadata` table. App writes one row per request. | 1-2 days |

## 14. Key Design Decisions

| Decision | Rationale |
| --- | --- |
